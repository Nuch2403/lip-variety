________________________________________
คำตอบที่แนะนำ (พูดสั้น กระชับ)
"Frontend (ส่วนหน้าที่ผู้ใช้มองเห็นและโต้ตอบได้) ของเราเป็น React (ไลบรารีสร้างหน้าเว็บ) + TypeScript (ภาษาโปรแกรมที่มีการกำหนดชนิดข้อมูล) ที่ทำงานฝั่ง Browser (โปรแกรมเปิดเว็บ) ทั้งหมด
มีสองส่วนหลักคือ User Side (ฝั่งผู้ใช้ทั่วไป) กับ Admin Side (ฝั่งผู้ดูแลระบบ)
User จะเดิน Journey (เส้นทางการใช้งาน) ตั้งแต่หน้า Home → เรียนรู้เรื่องลิปสติก → ทำ Quiz (แบบทดสอบ) 5 ขั้นตอน → รับ Recommendation (คำแนะนำสินค้า)
Admin จะจัดการข้อมูลสินค้า แบรนด์ เฉดสี ผ่าน Dashboard (หน้าจัดการข้อมูล) ที่เราสร้างไว้
สไตล์ทั้งหมดใช้ Tailwind CSS (เครื่องมือจัดหน้าตาเว็บ) ข้อมูลวิ่งผ่าน Supabase (บริการ Backend บนคลาวด์) ซึ่งเป็นทั้ง Database (ฐานข้อมูล) และ Authentication (ระบบล็อกอิน)"

Route Entry Point คืออะไร
Entry Point (จุดเริ่มต้น) = "ประตูทางเข้าแรก" ของแอป
เปรียบเหมือนอาคาร — ก่อนจะเข้าห้องไหนก็ต้องผ่านประตูใหญ่ก่อน
Browser (โปรแกรมเปิดเว็บ) เปิด URL (ที่อยู่เว็บ)
      ↓
index.html  ← HTML shell (โครงกระดูกหน้าเว็บ) ว่างเปล่า มีแค่ <div id="root">
      ↓
main.tsx    ← React "จุดระเบิด" สั่งให้แอปทำงาน
      ↓
App.tsx     ← "แผนที่" บอกว่า URL ไหน → แสดง Component (ชิ้นส่วน UI) อะไร
      ↓
หน้าที่ผู้ใช้เห็นจริง ๆ
Route (เส้นทาง) = กฎที่บอกว่า "ถ้า URL เป็น /quiz/step1 ให้แสดงหน้า QuizStep1"
Entry Point = ไฟล์แรกที่ทุกอย่างเริ่มต้นจากที่นั่น ก็คือ main.tsx

Frontend ในที่นี้หมายความว่าอะไร
Frontend (ส่วนหน้า) = ทุกอย่างที่รันใน Browser (โปรแกรมเปิดเว็บ) ของผู้ใช้
┌─────────────────────────────────────────┐
│              Browser (โปรแกรมเปิดเว็บ)  │
│                                         │
│  HTML + CSS + JavaScript  ← Frontend   │
│  (React, Tailwind, Router)              │
└────────────────┬────────────────────────┘
                 │ HTTP Request (คำขอข้อมูล)
┌────────────────▼────────────────────────┐
│              Supabase                   │
│  Database + Auth + Storage  ← Backend  │
│  (ฐานข้อมูล + ล็อกอิน + เก็บไฟล์)      │
└─────────────────────────────────────────┘
	Frontend (ส่วนหน้า)	Backend (ส่วนหลังบ้าน)
รันที่ไหน	Browser (เบราว์เซอร์ผู้ใช้)	Server (เซิร์ฟเวอร์ Supabase)
ทำอะไร	แสดงผล, รับ Input (ข้อมูลจากผู้ใช้), Quiz Logic (ตรรกะแบบทดสอบ)	เก็บข้อมูล, Auth (ล็อกอิน), Query (ดึงข้อมูล)
ไฟล์ในโปรเจกต์	ทุกอย่างใน src\	Supabase (อยู่ Cloud)
ภาษา	TypeScript / React	SQL (ภาษาฐานข้อมูล) + Supabase RPC (ฟังก์ชันบนเซิร์ฟเวอร์)

React + TypeScript คืออะไร
________________________________________
React คือ
Library (ชุดเครื่องมือสำเร็จรูป) สำหรับสร้าง UI (ส่วนติดต่อผู้ใช้) โดย Facebook/Meta
แทนที่จะเขียน HTML ปกติ → เขียนเป็น Component (ชิ้นส่วน UI ที่นำกลับมาใช้ซ้ำได้)
Navbar (แถบเมนู) + Hero (ภาพหลัก) + QuizCard (การ์ดแบบทดสอบ) + Footer (ส่วนล่าง)  →  รวมกันเป็นหน้าเว็บ
"สร้าง UI เป็นชิ้น ๆ แล้วประกอบกัน"
________________________________________
TypeScript คือ
JavaScript (ภาษาโปรแกรมของเว็บ) ที่มีการกำหนดชนิดข้อมูล (Type)
// JavaScript ปกติ — ไม่รู้ว่า shade คืออะไร
function score(shade) { ... }

// TypeScript — รู้ชัดเจน ผิดแจ้งเตือนทันที
function score(shade: Shade): number { ... }
"ช่วยให้โค้ดมีความชัดเจน จับ Bug (ข้อผิดพลาด) ได้ตั้งแต่ตอนพัฒนา ก่อนถึงมือผู้ใช้"

การตกแต่ง UI — Tailwind CSS
________________________________________
Tailwind CSS คืออะไร
CSS Framework (โครงสร้างพื้นฐานสำหรับจัดสไตล์) แบบ Utility-First (ใส่ class เล็ก ๆ ตรงจุดที่ต้องการเลย)
แทนที่จะเขียน CSS (คำสั่งจัดสไตล์) แยกไฟล์ → ใส่ class ตรงใน HTML/JSX (โค้ดหน้าเว็บ) เลย
// แบบเดิม (CSS แยกไฟล์)
<button class="my-button">คลิก</button>

// Tailwind — ใส่ style (สไตล์) ตรงเลย
<button className="bg-red-800 text-white px-4 py-2 rounded">
  คลิก
</button>
"Style (สไตล์) อยู่ติดกับ Component (ชิ้นส่วน) เลย ไม่ต้องสลับไฟล์"

อธิบาย Algorithm (ขั้นตอนการคำนวณ) — Recommendation Engine (ระบบแนะนำสินค้า)
________________________________________
ภาพรวม: ทำงาน 3 ขั้น
1. ดึงข้อมูลจาก Database (ฐานข้อมูล)  →  2. คำนวณคะแนน (Scoring)  →  3. เรียงแล้วคืน Top 3
________________________________________
ขั้น 1 — ดึงข้อมูล (Fallback 3 ระดับ = แผนสำรอง 3 ชั้น)
ไฟล์: src\features\recommendations\api\fetchRecommendations.ts
ไม่ได้ดึงทุกอย่างมาแล้วค่อยกรอง แต่ กรองตั้งแต่ใน Database (ฐานข้อมูล)
ลอง Strict (เข้มงวด) ก่อน  →  undertone (โทนสีใต้ผิว) ตรงกันเป๊ะ + depth (ความเข้มสี) ตรง
    ↓ ถ้าได้ 0 รายการ
ลอง Neutral (กลาง)          →  undertone ตรง หรือ neutral (โทนกลาง) ก็ได้
    ↓ ถ้าได้ 0 รายการ
ลอง Depth Only               →  เอา depth (ความเข้มสี) ตรงอย่างเดียว ไม่สนใน undertone
ป้องกันไม่ให้หน้า Results (ผลลัพธ์) ว่างเปล่าแม้ข้อมูลในฐานจะน้อย
________________________________________
ขั้น 2 — คำนวณคะแนน (Scoring = การให้คะแนน)
ไฟล์: src\features\recommendations\model\scoring.ts
      src\features\recommendations\data\constants.ts
แต่ละเฉดสีจะได้คะแนนสะสมจาก 6 ปัจจัย
ปัจจัย	คะแนนสูงสุด	ตัวอย่าง
Undertone (โทนสีใต้ผิว) ตรงกัน	+0.60	ผู้ใช้เลือก warm (อุ่น) → เฉดที่เป็น warm ได้เต็ม
Undertone เป็น Neutral (กลาง)	+0.32	เฉด neutral เข้ากับทุก undertone ได้บ้าง
Depth (ความเข้มสี) ตรงกับ Skin Tone (โทนผิว)	+0.28	ผิวแทน → depth: medium/deep ได้คะแนน
Occasion (โอกาสใช้งาน) × Depth	+0.05–0.30	Party → deep (เข้ม) ได้ +0.30, Daily → light (อ่อน) ได้ +0.20
Color Family (กลุ่มสี) × Occasion	+0.05–0.28	Party → red/berry ได้บวก, Office → nude/brown ได้บวก
Finish (ลักษณะผิวสัมผัสลิป) × Occasion	+0.01–0.04	Party → metallic/shimmer ได้บวก, Office → matte ได้บวก
Durability (ความทนทาน) ตรง	+0.02–0.08	เลือกทนสูง → longevity (อายุการใช้งาน): high ได้คะแนน
________________________________________
ขั้น 3 — เรียงและคัดเลือก
เรียงจากคะแนนสูง → ต่ำ
    ↓
ตัด Product (สินค้า) ซ้ำออก (1 Product = 1 ที่)
    ↓
คืน Top 3 (3 อันดับแรก)
________________________________________
ตัวอย่างจริง
ผู้ใช้: ผิว tan (แทน), undertone warm (โทนอุ่น), occasion Party, ทนทาน 5
เฉดสีแดง (red) + undertone warm + depth deep + finish metallic
  +0.60  undertone (โทนสีใต้ผิว) ตรง
  +0.28  depth (ความเข้มสี) ตรงกับผิว tan
  +0.30  Party ชอบ deep (เข้ม)
  +0.28  Party ชอบ red (แดง)
  +0.04  metallic (เมทัลลิก) เหมาะ Party
─────────────────────────────
  = 1.50  ← คะแนนสูงมาก ติด Top 3 แน่นอน
